FG DNA — CANONS v1.4
Статус: working
Роль документа: внутренний фильтр решений для FG

0. Назначение
Этот документ нужен для трёх вещей:

старта каждой рабочей сессии;
проектирования UX;
архитектурных и продуктовых решений.
Каноны не запрещают развитие.
Они защищают смысл FG от шума, FOMO и подмены цели.

FG — это финансовый инструмент и когнитивная среда инвестора.
Мы строим систему понимания, а не систему давления.

1. Семь инвариантов FG
1. Хороший UX даёт ровно столько, чтобы захотелось сделать следующий шаг
Не больше.
Не быстрее.
Не агрессивнее.

2. FG помогает думать, а не “помогает заработать”
Мы создаём среду понимания, а не инструмент принуждения.

3. FG — когнитивный слой инвестора
Продукт формирует способ мышления, а не управляет поведением пользователя.

4. Данные не скрываются системой
Система может менять только визуальный вес информации.
Скрытие допустимо только по явному действию пользователя.

5. FG может ускорять действия, но не ускоряет выводы
Исполнение может стать быстрее.
Решение всегда остаётся за человеком.

6. Чем резче рынок, тем спокойнее интерфейс
UI не должен усиливать эмоции рынка.

7. Рост строится через доверие и ясность, а не через срочность и FOMO
FG распространяется не через давление, а через ощущение честности, контроля и интеллектуального уважения к пользователю.

2. Принцип смелой ясности
FG допускает смелые UX- и архитектурные решения, если они:

снижают когнитивную нагрузку;
усиливают понимание структуры рынка;
повышают прозрачность;
усиливают контроль пользователя.
Смелость запрещена там, где она усиливает эмоциональное давление.

FG — спокойный, но не слабый.
Выразительность допустима. Манипуляция — нет.

3. Жёсткие запреты
NO
Формулировки рекомендаций: “лучшее решение”, “стоит купить”, “сейчас самое время”.
Эмоционально агрессивные визуальные паттерны: мигание, драматичные пульсации, панические акценты.
Скрытие данных по инициативе системы.
Автоматические действия, меняющие траекторию решения пользователя.
4. Разрешённые действия
YES
Быстрые и обратимые действия: переключения, zoom, undo, раскрытие слоёв, навигация.
Нейтральные подсказки без CTA.
Де-акцент вторичного без изменения структуры данных.
Выразительные интерфейсные решения, если они структурируют, а не драматизируют.
Базовый формат нейтральной подсказки:

“Обычно в этом месте смотрят …”
без оценки;
без давления;
без навязывания следующего действия.
5. Адаптивность FG: минимальный рабочий слой
A. Логи поведения без интерпретаций
Фиксируются только наблюдаемые факты:

tf_switch_burst
zoom_oscillation
hover_long
overload_detected
B. Реакции уровня L1
Только изменение визуального веса:

приглушение вторичного;
снижение анимаций;
интерфейс отступает, а не вмешивается.
C. Реакции уровня L2
Максимум одна строка:

нейтральный тон;
без советов;
без оценок;
без давления.
D. Переключатель адаптивности
Адаптивная помощь: Вкл / Выкл

Требования:

всегда доступен;
по умолчанию: Вкл;
Off допустим как рабочий режим в dev.
6. Пороговые сценарии v1
S1. Focus session
Условия:

около 10 минут;
один тикер;
без хаотичных действий.
Реакция:

UI минимизируется;
вторичное уходит на задний план.
S2. TF burst
Условия:

>=5 смен timeframe за <=20 секунд.
Реакция:

мягкая визуальная опора;
одна нейтральная подсказка.
S3. Overload
Условия:

индикаторов больше порога N;
плюс хаотичные действия.
Реакция:

вторичное приглушается;
структура остаётся честной;
данные не скрываются.
7. Состояние рынка
Уровни
M1 — спокойный
M2 — напряжённый
M3 — событие
Правило
При M2 / M3:

меньше анимаций;
спокойнее цвета;
ноль визуальной агрессии.
Рынок может быть резким.
Интерфейс не должен становиться резче вместе с ним.

8. Метрики успеха
FG измеряет не клики и не возбуждение, а качество мыслительного цикла.

Основные метрики
Завершённость анализа
Новость → график → метрика → выход без хаоса.

Спокойствие сессии
Снижение серий хаотичных действий.

Возврат по смыслу
Возврат к тому же тикеру или сценарию через событие, а не через случайный импульс.

Метрики — это наблюдаемые следствия.
Они не являются прямым доказательством внутренних ощущений пользователя.

9. Рабочее правило архитектора
Перед любым изменением задать два вопроса:

Это снижает когнитивную нагрузку?
Это делает систему честнее и прозрачнее?
Если ответ нет, изменение откладывается.

10. Базовая формула FG
FG ускоряет действие, но не ускоряет решение.
FG не обещает заработать, а помогает думать.
FG не давит, а создаёт пространство, в котором человеку не страшно понимать деньги.
