# План визуального поведения индикаторов в Phase 9

## Статус

Рабочая декомпозиция для `Phase 9 — Broad Feature / Design Phase`.

Фаза 9 начинается поверх закрытых архитектурных решений, а не вместо них. `Phase 8` уже закрыла архитектурную модель слоя индикаторов: владельца состояния, минимальное runtime-ядро, границы renderer-слоёв, safe-зоны и retained frontier вокруг `MultiPaneChart`.

## 1. Главная формула

Задача 9 пока не про добавление новых индикаторов.

Задача 9:

Довести текущие 4 пункта меню индикаторов до честного, стабильного и проверяемого визуального поведения в `Expanded`.

Текущие 4 индикатора:

- `MA`
- `EMA`
- `RSI`
- `Volume`

Пользовательский сценарий:

`пользователь выбирает тикер -> открывает Expanded -> открывает меню индикаторов -> выбирает индикатор -> график визуально подтверждает выбор`

Успех не считается только по клику или изменению состояния.

Успех есть только тогда, когда пользователь видит корректный визуальный результат.

## 2. Почему новые индикаторы отложены

Кандидаты вроде `Bollinger Bands`, `ATR` и `OBV` остаются важными, но не входят в первый проход задачи 9.

Причины:

- текущий UI уже обещает 4 индикатора;
- эти 4 индикатора сначала должны работать честно и стабильно;
- новые индикаторы увеличат неопределённость;
- `ATR` и `OBV` затрагивают lower-pane behavior;
- нижние панели сейчас связаны с retained frontier вокруг `MultiPaneChart`.

Поэтому первый проход задачи 9 — не расширение набора индикаторов.

Это стабилизация текущего обещания интерфейса.

## 3. Архитектурная база после Phase 8

Принято после `Phase 8`:

- минимальное ядро состояния индикаторов = `ChartContext.activeIndicators`;
- владелец состояния индикаторов = `ChartContext`;
- `ChartRenderer`, `useChartIndicators` и `MultiPaneChart` не владеют состоянием индикаторов;
- renderer-слои только читают состояние и применяют branch-specific display behavior;
- `ChartCanvas` = более полная основная ветка рендера;
- `MultiPaneChart` = узкая gated-ветка для текущих нижнепанельных сценариев;
- `compact` не является доказанным indicator mode;
- ошибки и failure semantics остаются во внешнем chart/failure layer.

## 4. Текущий визуальный контракт

Текущая принятая модель:

| Индикатор | Текущий смысл |
|---|---|
| `MA` | overlay поверх цены в `ChartCanvas` |
| `EMA` | overlay поверх цены в `ChartCanvas` |
| `RSI` | bottom pane только под точным `MultiPaneChart` gate |
| `Volume` | bottom pane только под точным `MultiPaneChart` gate |

Точный `MultiPaneChart` gate:

- `Expanded`
- ровно один видимый индикатор
- индикатор = `rsi` или `volume`

Смешанные visible sets сейчас остаются в `ChartCanvas`.

Forced lower-pane parity для смешанных наборов нет.

## 5. Главная граница

Нельзя заранее считать смешанные наборы рабочими нижнепанельными сценариями.

### Один lower-pane indicator за раз

В первом проходе Phase 9 текущая безопасная граница такая:

- overlay-индикаторы (`MA`, `EMA`) могут сосуществовать;
- lower-pane индикаторы (`RSI`, `Volume`) рассматриваются как взаимоисключающие;
- одновременно активный lower-pane индикатор — один;
- `RSI + Volume` не входит в первый проход;
- это не финальное продуктовое ограничение навсегда, а текущая архитектурно-безопасная граница до отдельного decision pass по нескольким нижним панелям.

| Сценарий | Статус |
|---|---|
| только `RSI` | базовая цель |
| только `Volume` | базовая цель |
| только `MA` | базовая цель |
| только `EMA` | базовая цель |
| `MA + EMA` | базовая overlay-цель |
| `MA / EMA + RSI` | продуктово желательно, но требует фактической проверки render path |
| `MA / EMA + Volume` | продуктово желательно, но требует фактической проверки render path |
| `RSI + Volume` | не первая цель |
| все 4 сразу | не первая цель |

## 6. Декомпозиция задачи 9

### 9.1 — Read-only anchor текущей цепочки индикаторов

Статус: completed

Цель:

Доказать текущую фактическую цепочку без патча.

Цепочка:

`Indicator menu -> ChartContext.activeIndicators -> render branch -> observable visual effect`

Проверить каждый индикатор: `MA`, `EMA`, `RSI`, `Volume`.

Обязательные факты:

- пункт меню существует;
- выбор проходит;
- состояние меняется в `ChartContext.activeIndicators`;
- renderer читает это состояние;
- появляется наблюдаемый визуальный эффект;
- выключение убирает эффект;
- смена тикера не оставляет старые линии или панели;
- смена timeframe / period не оставляет старые линии или панели;
- нет критических ошибок;
- масштаб и навигация не ломаются.

Выход:

`indicator -> state path -> render path -> visual effect -> known gap / no gap`

Запрещено в `9.1`:

- не патчить;
- не добавлять новые индикаторы;
- не менять правила сочетаний;
- не делать вывод "работает" без наблюдаемого визуального эффекта.

Итог 9.1:

- `9.1A code anchor` выполнен;
- `9.1B runtime visual evidence` выполнен на `3100` и `3101`;
- текущие 4 индикатора не являются мёртвыми пунктами меню;
- одиночные `MA`, `EMA`, `RSI`, `Volume` дают observable visual effect;
- `MA + EMA` работает как overlay-сценарий;
- `RSI` и `Volume` работают как взаимоисключающие lower-pane сценарии;
- mixed scenarios `MA/EMA + RSI/Volume` технически работают через fallback, но не дают целевой UX `overlay + lower-pane`;
- следующий шаг: `9.2 — decision: минимальный visual contract для overlay + one lower-pane`.

### 9.2 — Минимальный визуальный контракт текущих 4 индикаторов

Статус: принято / закрыто.

Цель:

Зафиксировать визуальный договор первого прохода для текущих четырёх индикаторов в `Expanded`.

Фаза `9.2` не пишет код. Она отвечает на вопрос:

`что пользователь имеет право включить -> где это должно появиться -> что график обязан сохранить неизменным`

#### Рабочая версия договора 9.2

В первом проходе `Expanded` поддерживает:

- price candles;
- ноль, одну или две overlay-линии на price pane: `MA`, `EMA`;
- максимум один lower-pane indicator: `RSI` или `Volume`.

Главная формула:

`price + optional MA + optional EMA + max one lower pane`

`MA` и `EMA` живут поверх цены.

`RSI` и `Volume` живут снизу.

Снизу в первом проходе может быть только один индикатор.

#### Разрешённые связки первого прохода

| Связка | Ожидаемое поведение |
|---|---|
| `MA` | одна линия поверх цены |
| `EMA` | одна линия поверх цены |
| `MA + EMA` | две линии поверх цены |
| `RSI` | одна нижняя панель `RSI` |
| `Volume` | одна нижняя панель `Volume` |
| `MA + RSI` | линия `MA` поверх цены + одна нижняя панель `RSI` |
| `EMA + RSI` | линия `EMA` поверх цены + одна нижняя панель `RSI` |
| `MA + Volume` | линия `MA` поверх цены + одна нижняя панель `Volume` |
| `EMA + Volume` | линия `EMA` поверх цены + одна нижняя панель `Volume` |
| `MA + EMA + RSI` | две линии поверх цены + одна нижняя панель `RSI` |
| `MA + EMA + Volume` | две линии поверх цены + одна нижняя панель `Volume` |

Это полный список разрешённых связок первого прохода.

`MA + EMA + Volume` включается по той же логике, что и `MA + EMA + RSI`: если разрешены две overlay-линии и один нижний индикатор, нижним индикатором может быть либо `RSI`, либо `Volume`.

#### Отложенные связки

В первом проходе не разрешены:

| Связка | Почему откладывается |
|---|---|
| `RSI + Volume` | это уже две нижние панели |
| `MA + EMA + RSI + Volume` | тоже требует две нижние панели |
| несколько lower-pane indicators одновременно | нужен отдельный договор по высоте, синхронизации, шкалам и поведению |
| новые индикаторы | сначала стабилизируются текущие четыре |
| передел всей многопанельной системы | не входит в `9.2` |

Важно: это не запрет навсегда.

Это означает только:

`две нижние панели не входят в первый проход`

Отдельная будущая задача по нескольким нижним панелям должна решить:

- как панели делят высоту;
- как они синхронизируются при прокрутке;
- как ведёт себя crosshair;
- как выглядят шкалы;
- как не перегрузить экран;
- как удалять и пересоздавать панели без визуального мусора;
- как сохранить стабильный вид цены.

#### Взаимоисключение lower-pane indicators

`RSI` и `Volume` в первом проходе являются взаимоисключающими lower-pane indicators.

Если пользователь включает `Volume`, когда уже активен `RSI`, `RSI` должен быть выключен или заменён на `Volume` честным UI-поведением.

Если пользователь включает `RSI`, когда уже активен `Volume`, `Volume` должен быть выключен или заменён на `RSI` честным UI-поведением.

`MA` и `EMA` при таком переключении lower-pane indicator должны оставаться включёнными.

Цель этого правила — не дать пользователю собрать неподдержанную комбинацию `RSI + Volume`, не скрывая при этом состояние графика.

#### Главный визуальный инвариант

При включении индикаторов сам ценовой график не должен становиться другим графиком.

Пользователь должен видеть тот же график цены, а не новый случайный вид.

При любых разрешённых связках запрещено:

- менять видимый временной участок без действия пользователя;
- менять плотность свечей;
- сдвигать график влево или вправо;
- менять масштаб так, будто это другой график;
- менять рисунок свечей;
- терять текущую позицию пользователя;
- превращать включение индикатора в скрытую смену режима графика;
- показывать разные ценовые картины для похожих связок;
- скрывать данные без явного действия пользователя.

Последний пункт является FG-инвариантом: система не должна скрывать данные по своей инициативе, допускается только изменение визуального веса информации.

#### Что разрешено менять

Если включается только `MA` или `EMA`, разрешено только:

- добавить линию `MA`;
- добавить линию `EMA`;
- показать две линии, если включены обе.

Нельзя менять сам график цены.

Если включается `RSI` или `Volume`, разрешено:

- добавить одну нижнюю панель;
- уменьшить высоту price pane, потому что экран делится между ценой и нижним индикатором.

Это единственное допустимое крупное визуальное изменение.

#### Что считается успешной отрисовкой

| Индикатор | Успешный результат |
|---|---|
| `MA` | overlay-линия появилась / исчезла |
| `EMA` | overlay-линия появилась / исчезла |
| `RSI` | bottom pane появилась / исчезла, если это единственный активный lower-pane indicator |
| `Volume` | bottom pane появилась / исчезла, если это единственный активный lower-pane indicator |

Требования для всех индикаторов:

- включение не должно ломать свечи;
- выключение должно полностью убирать визуальный слой;
- смена тикера должна пересчитывать индикатор;
- смена timeframe / period должна пересчитывать индикатор;
- старые данные не должны оставаться на новом графике;
- пустая панель не должна оставаться после выключения;
- не должно быть скрытого рассинхрона между меню и графиком.

#### Что считается неправильным результатом

Неправильно, если после включения индикатора:

- график прыгает;
- свечи становятся другими;
- меняется видимый участок;
- исчезает часть графика;
- меняется плотность свечей;
- price pane ведёт себя как новый график;
- `MA` или `EMA` пропадают при включении `RSI` или `Volume`;
- `RSI` или `Volume` рисуются внутри price pane вместо нижней панели;
- нижняя панель появляется, но ломает восприятие цены;
- `RSI` и `Volume` включаются одновременно в первом проходе.

#### Текущая реальность кода

Сейчас текущая правда такая:

- `MA` и `EMA` работают как линии поверх цены только в `ChartCanvas`;
- `RSI` и `Volume` попадают в нижнюю панель только при узком условии;
- это условие: `Expanded`, ровно один видимый индикатор, и этот индикатор — `RSI` или `Volume`;
- смешанные связки сейчас остаются в другой ветке отрисовки;
- поэтому текущая система ещё не даёт честный договор `overlay + one lower-pane`.

Именно поэтому `9.2` нужна как accepted decision перед реализацией.

#### Что 9.2 не переоткрывает

Фаза `9.2` не меняет:

- владельца состояния индикаторов;
- владельца данных;
- владельца выбора timeframe / interval;
- `compact`;
- закрытую `Phase 8`;
- всю многопанельную систему;
- поддержку новых индикаторов.

Состояние индикаторов остаётся в `ChartContext.activeIndicators`, а renderer-ветки только читают это состояние. Это уже принято в закрытой `Phase 8`.

#### Ограниченный хвост Phase 8, который признаётся

Да, retained хвост есть:

текущая многопанельная ветка ещё не умеет честно совмещать `MA/EMA` поверх price pane и одну нижнюю панель `RSI` или `Volume` без визуальных скачков и расхождений.

Но этот хвост ограниченный.

Он не означает:

- переделать всё;
- вернуться в `Phase 8`;
- делать несколько нижних панелей;
- добавлять новые индикаторы;
- трогать `compact`.

Он означает только:

после согласования `9.2` нужна отдельная точная проверка, где безопасно провести линии `MA/EMA` в price pane многопанельной ветки и как не сломать график цены.

Выход:

`accepted visual contract -> allowed combinations -> deferred combinations -> invariant -> implementation boundary`

### 9.3 — Стабилизация `MA / EMA`

Статус: completed / закрыто.

Цель:

Стабилизировать overlay-индикаторы `MA` и `EMA`.

Это самый безопасный слой, потому что `MA` и `EMA` живут поверх основного графика цены и не требуют открытия lower-pane model.

Проверить `MA`:

- линия появляется;
- линия исчезает;
- линия не ломает свечи;
- линия пересчитывается при смене тикера;
- линия пересчитывается при смене timeframe / period;
- линия не остаётся после выключения.

Проверить `EMA`:

- линия появляется;
- линия исчезает;
- линия не ломает свечи;
- линия пересчитывается при смене тикера;
- линия пересчитывается при смене timeframe / period;
- линия не остаётся после выключения.

Проверить `MA + EMA`:

- обе линии могут быть видимы одновременно;
- линии визуально различимы;
- выключение одной не ломает вторую;
- масштаб графика не сбрасывается неожиданно;
- свечи остаются читаемыми.

Выход:

Текущий overlay-слой индикаторов считается стабильным.

Итог 9.3:

- `MA` появляется и исчезает как overlay-линия.
- `EMA` появляется и исчезает как overlay-линия.
- `MA + EMA` работают вместе.
- Выключение `MA` не ломает `EMA`.
- Выключение `EMA` оставляет свечи видимыми.
- Нижняя панель не появляется для `MA / EMA`.
- Runtime QA подтвердил, что после смены `SBER -> GAZP` при активных `MA + EMA` старые overlay-линии не остаются.
- Смена `15m -> 1h` при активных `MA + EMA` остаётся стабильной.
- Console errors: 0.

Фикс 9.3:

- Изменён один файл: `fingineerwebapp/src/components/Results/Chart/hooks/useChartIndicators.js`.
- Причина дефекта: ключ кэша `MA / EMA` не различал конкретный набор свечей.
- При смене тикера старый расчёт мог переиспользоваться, если совпадали `id`, `params`, длина данных, `currentCandleType`, `currentInterval`, `currentTimeframe`.
- Решение: в ключ кэша добавлена `sourceIdentity` по свечам только для `MA / EMA`.
- `sourceIdentity` включает первое время свечи, последнее время свечи, первое закрытие и последнее закрытие.
- `RSI`, `Volume`, `MultiPaneChart`, `ChartRenderer`, `ChartContext` не менялись.

Runtime evidence 9.3:

- Среда: `[3000]`, `http://127.0.0.1:3000`.
- Сценарий: `SBER`, Expanded, `15m`, `3mth`, включены `MA + EMA`.
- Действие: смена тикера `SBER -> GAZP`.
- Ожидание: свечи и `MA / EMA` должны перейти в область цены `GAZP`; старые линии не должны остаться.
- Факт: `GAZP` загрузился, ценовая область стала `150.x`, маркеры `MA / EMA` ушли в новую область `GAZP`, старая `SBER`-полоса не обнаружена.
- Вердикт: `FIX CONFIRMED`.
- Visual stability: `STABLE`.
- Recommendation: `READY TO CLOSE 9.3`.

### 9.4 — Стабилизация `RSI / Volume` как одиночных lower-pane сценариев

Цель:

Стабилизировать нижнепанельные индикаторы только внутри безопасного первого контура.

Первый контур:

- только `RSI`
- только `Volume`

Первый контур намеренно ограничен одиночными lower-pane сценариями. Одновременный `RSI + Volume` не проверяется как целевой сценарий в `9.4`, потому что это уже задача про несколько нижних панелей, layout, sync и retained `MultiPaneChart` frontier.

Проверить `RSI`:

- включение создаёт bottom pane;
- основной график остаётся читаемым;
- высота панели адекватна;
- уровни `RSI` отображаются согласно текущему контракту;
- выключение убирает панель;
- смена тикера пересчитывает `RSI`;
- смена timeframe / period пересчитывает `RSI`;
- пустая панель не остаётся после выключения.

Проверить `Volume`:

- включение создаёт bottom pane;
- объёмы соответствуют текущему графику;
- основной график остаётся читаемым;
- высота панели адекватна;
- выключение убирает панель;
- смена тикера пересчитывает `Volume`;
- смена timeframe / period пересчитывает `Volume`;
- пустая панель не остаётся после выключения.

Проверить переключение:

- `RSI -> выключить -> Volume`
- `Volume -> выключить -> RSI`
- `RSI -> Volume`
- `Volume -> RSI`

Нужно доказать:

- старая панель не остаётся;
- новая панель появляется;
- пустой нижний блок не остаётся;
- ошибка не появляется;
- масштаб и навигация графика не ломаются.

Выход:

`RSI` и `Volume` работают как одиночные lower-pane сценарии.

### 9.5 — Правила сочетаний индикаторов

Цель:

Реализовать правила сочетаний индикаторов по принятому `9.2` visual contract.

`9.5` не принимает новый visual contract. Она должна привести UI/state/render behavior к уже принятому договору `9.2`.

Разрешить в первом проходе:

- `MA`
- `EMA`
- `MA + EMA`
- `RSI`
- `Volume`
- `MA + RSI`
- `EMA + RSI`
- `MA + Volume`
- `EMA + Volume`
- `MA + EMA + RSI`
- `MA + EMA + Volume`

Запретить или честно предотвращать в первом проходе:

- `RSI + Volume`
- `MA + EMA + RSI + Volume`
- несколько lower-pane indicators одновременно

`RSI + Volume` требует отдельного future decision pass по нескольким нижним панелям. Этот pass должен отдельно решить layout, высоты панелей, sync, hover/crosshair behavior, scale ownership и связь с retained `MultiPaneChart` frontier.

Обязательное правило первого прохода:

- `MA` и `EMA` не конфликтуют между собой;
- `MA` и `EMA` не конфликтуют с одним lower-pane indicator;
- `RSI` и `Volume` конфликтуют между собой;
- при переключении `RSI <-> Volume` overlay-индикаторы `MA/EMA` не должны выключаться;
- UI не должен показывать активной связку, которую renderer не может честно отрисовать.

Причина:

Смешанные visible sets `MA/EMA + RSI/Volume` теперь являются принятой целью первого прохода, но текущий render path ещё не доказан как visual-safe для этого договора.

Поэтому `9.5` должна идти после `9.2` и опираться на точный code/runtime anchor:

`Indicator menu -> ChartContext.activeIndicators -> renderer branch -> price pane overlays -> one lower pane`

Выход:

- разрешённые связки реализованы честно;
- неподдержанные связки предотвращены или заменяются честным UI-поведением;
- `RSI + Volume` и две lower panes отложены до отдельного решения;
- меню индикаторов и график не расходятся.

### 9.6 — Проверка визуальной честности

Цель:

Убедиться, что UI не врёт пользователю.

Меню индикаторов и график должны быть согласованы.

Проверить:

- если индикатор включён в меню, он виден на графике;
- если индикатор выключен в меню, он не виден на графике;
- если индикатор временно нельзя показать в выбранной комбинации, поведение UI должно быть честным;
- пользователь не должен думать, что индикатор включён, если график его не показывает;
- визуальный результат остаётся стабильным после смены тикера / timeframe / period.

Выход:

Меню индикаторов и график согласованы.

### 9.7 — Runtime QA

Цель:

Проверить сценарий как пользовательский поток.

Базовые среды:

- `3000` = normal dev
- `3100` = REST QA
- `3101` = app / non-REST QA

Обязательный формат evidence:

- target found;
- action attempted;
- action succeeded / failed;
- observable effect detected;
- blocker if failed.

Обязательные сценарии:

- открыть `Expanded`, включить `MA`, увидеть линию;
- выключить `MA`, линия исчезает;
- включить `EMA`, увидеть линию;
- включить `MA + EMA`, обе линии видны;
- включить только `RSI`, появляется bottom pane;
- выключить `RSI`, bottom pane исчезает;
- включить только `Volume`, появляется bottom pane;
- выключить `Volume`, bottom pane исчезает;
- включить `MA + RSI`, увидеть `MA` поверх цены и `RSI` в bottom pane;
- включить `EMA + RSI`, увидеть `EMA` поверх цены и `RSI` в bottom pane;
- включить `MA + Volume`, увидеть `MA` поверх цены и `Volume` в bottom pane;
- включить `EMA + Volume`, увидеть `EMA` поверх цены и `Volume` в bottom pane;
- включить `MA + EMA + RSI`, увидеть обе overlay-линии поверх цены и `RSI` в bottom pane;
- включить `MA + EMA + Volume`, увидеть обе overlay-линии поверх цены и `Volume` в bottom pane;
- переключить `RSI -> Volume` при включённом `MA` или `EMA`, overlay-линии остаются видимыми;
- переключить `Volume -> RSI` при включённом `MA` или `EMA`, overlay-линии остаются видимыми;
- переключить тикер с активным overlay-индикатором;
- переключить timeframe / period с активным overlay-индикатором;
- переключить тикер с активным `RSI`;
- переключить timeframe / period с активным `Volume`.

Что считается провалом:

- пункт меню активен, но индикатор не виден;
- индикатор виден, но пункт меню выключен;
- старая линия остаётся после смены тикера;
- пустая панель остаётся после выключения;
- масштаб графика неожиданно сбрасывается;
- появляется ошибка;
- одновременно активны `RSI + Volume` или несколько lower-pane indicators;
- пользовательский сценарий нельзя честно объяснить.

## 7. Явно вне первого прохода

Не входит:

- добавление `Bollinger Bands`;
- добавление `ATR`;
- добавление `OBV`;
- полный redesign `MultiPaneChart`;
- полная поддержка нескольких нижних панелей;
- forced parity между `ChartCanvas` и `MultiPaneChart`;
- forced parity между `compact` и `expanded`;
- отдельная failure-модель индикаторов;
- redesign каталога индикаторов;
- redesign реестра индикаторов;
- широкая модель будущих индикаторов.

## 8. Риски

### Риск 1 — смешать продуктовую цель и архитектурную готовность

Продуктово желательны:

- `MA / EMA + RSI`
- `MA / EMA + Volume`

Но архитектурную готовность сначала нужно доказать.

### Риск 2 — открыть `MultiPaneChart` слишком широко

Retained frontier вокруг `MultiPaneChart` точный и bounded.

Он не даёт права на полный rewrite.

### Риск 3 — принять клик за результат

Выбор в меню не равен успешной отрисовке.

### Риск 4 — перегрузить пользователя

Даже если все 4 индикатора можно технически включить, это не значит, что это хороший первый пользовательский сценарий.

### Риск 5 — сломать закрытые решения Phase 8

Не переоткрывать:

- кто владеет состоянием индикаторов;
- что является минимальным runtime-ядром;
- должны ли renderer paths владеть состоянием;
- нужно ли тянуть `compact` в indicator parity.

## 9. Решение по приоритету

Порядок работы:

1. `9.1` — read-only anchor — completed.
2. `9.2` — минимальный визуальный договор — принято / закрыто.
3. `9.3` — стабилизация `MA / EMA` — completed / закрыто.
4. `9.4` — стабилизация `RSI / Volume` как одиночных lower-pane сценариев.
5. `9.5` — правила сочетаний.
6. `9.6` — проверка честности меню и графика.
7. `9.7` — runtime QA.

## 10. Финальная формула

Задача 9 = сделать текущие 4 индикатора честными, видимыми и стабильными в `Expanded`.

Не добавлять новые индикаторы.

Не открывать широкий redesign.

Не строить терминал "как у всех".

Сначала доказать и стабилизировать:

`menu selection -> activeIndicators -> render branch -> visual effect`

Только после этого возвращаться к новым индикаторам:

- `Bollinger Bands`
- `ATR`
- `OBV`
