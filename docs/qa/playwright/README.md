# FG2 QA / Playwright

## Назначение

Этот каталог нужен для постоянной QA-структуры вокруг браузерных проверок во время выполнения в `FG2`.

Здесь фиксируются рабочие запросы и сценарии для `Codex + Playwright MCP`, когда нужно открыть приложение в браузере, выполнить реальные действия и вернуть проверяемые доказательства.

`VS Code integrated browser` остаётся отдельным ручным путём отладки. Он полезен для точек останова, ручного трассирования и локальной отладки в редакторе, но не заменяет автономные браузерные проверки через `Playwright MCP`.

## Структура папок

- `docs/qa/playwright/prompts`
  Здесь лежат постоянные запросы для `Codex`, которые задают формат браузерных проверок.
- `docs/qa/playwright/test-scenarios`
  Здесь лежат постоянные сценарии и контракты проверок для повторяемых QA-прогонов.
- `tmp/qa/screenshots`
  Сюда сохраняются временные снимки экрана из проверок.
- `tmp/qa/reports`
  Сюда сохраняются временные отчёты прогона и другие артефакты.

## Разделение ответственности

- Приёмочные проверки
  Проверяют, что пользовательский сценарий проходит целиком и продукт остаётся рабочим.
- Проверки ограничений
  Проверяют, что доменные ограничения реально применяются, а не только описаны в логике.
- Сбор доказательств по chart bug
  Собирает доказательства по симптому: цель, действие, состояние до/после, `console`, `network`, снимки экрана.
- Ручная отладка и автономные браузерные проверки
  Ручная отладка через `VS Code integrated browser` нужна для точек останова и ручного анализа. Автономные браузерные проверки через `Codex + Playwright MCP` нужны для воспроизводимой проверки без ручных действий пользователя.

## Правила артефактов

- Снимки экрана сохраняются в `tmp/qa/screenshots`.
- Отчёты прогона сохраняются в `tmp/qa/reports`.
- Постоянные запросы и сценарии хранятся в `docs/qa/playwright`.
- Случайные временные заметки не должны храниться в `docs/qa/playwright`.

## Правила именования

- Имена снимков экрана
  Использовать понятный сценарий и шаг: `fg2-<flow>-<step>-<state>.png`.
- Имена отчётов
  Использовать сценарий и тип результата: `fg2-<flow>-report.md`.
- Имена сценариев
  Использовать короткое описание проверяемой логики: `<topic>-<scope>.md`.
- Имена запросов
  Использовать имя режима проверки: `<purpose>.md`.

## Правила выполнения для запросов Codex

- Использовать `Playwright MCP`.
- Не делать patch, если это явно не запрошено.
- Возвращать доказательства, а не догадки.
- Не заявлять успех, если действие инструмента реально не выполнялось.
- Если цель недоступна или отключена, возвращать точную причину блокировки.
- Если `console` или `network` cumulative, это нужно явно указать.

## Текущие подтверждённые сценарии в FG2

- search `SBER`
- открытие компактного графика
- открытие расширенного графика
- переключение временного диапазона
- смена типа графика
- наведение внутри области графика
- сохранение работоспособности после изменения размера
- пример матричного ограничения, где отдельный интервал может быть недоступен для конкретного временного диапазона
